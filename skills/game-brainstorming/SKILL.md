# Game Brainstorming (2D Godot)

> 把"我想做X"打磨成可写 GDD 的设计输入。
> 走完本技能,产出 `gdd-author` 可直接消费的"概念包"。

## 0. 路由(进入技能先问)

用 `ask_user` **单题 ≤ 4 选 1** 让用户选:

| 选项 | 含义 | 走法 |
|------|------|------|
| **A. 从零构思** | 有想法但还没成文 | 走完整 5 阶段 |
| **B. 细化现有想法** | 已有粗略概念,想补完 | 跳到阶段 3 之后 |
| **C. 评估 / Pivot** | 已有 GDD 雏形,想重新评估方向 | 走 1 阶段,再决定保留/重做 |

不堆 4 题。

## 1. 阶段 1 — Hook 一句话(必须 ≤ 30 字)

反复问到能用一句中文说清:

```
<类型/genre> + <核心 hook/差异化> + <平台/受众>
```

例:
- "2D 像素平台跳跃 + 时间倒流解谜 + 个人电脑" ✓
- "想做一款好玩的游戏" ✗ (太泛)

**失败模式**: 用户三句话内说不清 → 强制让用户先填 1 句话再说。

## 2. 阶段 2 — 设计支柱(3-5 条,每条 ≤ 12 字)

支柱是**决策过滤器**。后续每一步都问:"这服务哪条支柱?"

每条支柱必须:
- 是**对玩家体验的承诺**,不是功能
- 可被违反时立刻发现
- 不超过 12 个汉字(或对应英文短句)

模板:
1. <核心感觉/情感>(例: "操作手感即正义")
2. <核心约束>(例: "单局 ≤ 5 分钟")
3. <核心反例>(例: "永不出现永久死亡")

**工具**: 对每个候选支柱问 "如果这游戏违反这条,会怎样?" 若无感则不是真支柱。

## 3. 阶段 3 — 核心循环(必须画 ASCII 流程图)

游戏 = 核心循环的反复执行。每个 2D 游戏都有 1-2 个核心循环,先定 1 个。

模板:
```
[输入] → [动作] → [反馈] → [进展/奖励] → (回输入)
```

例(平台跳跃):
```
[跑 + 跳] → [避障/收集] → [扣血/加分] → [抵达终点 / 重生] → (回跑+跳)
```

**失败模式**: 画不出图 → 没想清楚核心动作,回去补 1 阶段。

## 4. 阶段 4 — 平台与体量

- 平台:Windows / Mac / Linux / Web(itch.io) / Android / iOS
- 单局时长(分钟):____
- 通关时长(小时):____
- 玩家人数:1 / 2-4 local / 异步联机
- 美术风格:像素 / 矢量 / 手绘 / 程序化
- 引擎:Godot 4.7(本套件假定)

## 5. 阶段 5 — 概念包产出

把以上 1-4 阶段打包,作为 `gdd-author` 的输入。建议落到 `design/concept.md`:

```markdown
# 概念包

## Hook
<一句话>

## 支柱
1. ...
2. ...
3. ...

## 核心循环
```
<ascii>
```

## 平台与体量
- 平台: ...
- 单局: ...
- 美术: ...

## 候选机制(2D 限定)
- [机制 1]: 1 句话描述
- [机制 2]: ...
- [机制 3]: ...

## 风险/未知
- <技术风险>
- <设计风险>
- <资产风险>
```

## 6. 衔接

概念包完成后,**默认下一步走 `gdd-author`**(用 `from-scratch` 模式)。
让用户先确认 "概念 OK" 再进 GDD。

## Anti-Patterns (拒绝这些)

- ❌ "先把代码跑起来再说设计" → 写完才发现核心循环跑不通,沉没成本
- ❌ "我加了一堆机制" → 不服务支柱的机制都是噪音
- ❌ "这是借鉴 X 游戏" → 必须说清楚**比 X 多什么 / 少什么**
- ❌ "想做 roguelike" → 类型不替代 hook,必须说清楚**这次**的 hook

## 何时退出

概念包用户已签字 → 调用 `gdd-author`,交接概念包路径。
用户明确说"先不写 GDD" → 退出,提示用户后续可手动触发 `gdd-author`。
