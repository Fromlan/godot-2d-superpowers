# GDD Section Rubric (每节的"完成度"自检)

每节写到能通过下面的问题清单, 才算"完成"。

## §0 文档说明

- [ ] 版本号 (semver, 例 0.1.0)
- [ ] 定位 (1 句话, 不超过 30 字)
- [ ] 单局时长 (分钟数, 不是"几小时")
- [ ] 目标平台 (具体, 例 "PC Steam", 不是 "PC")
- [ ] 本文档作用 (1 句话, 说清楚什么写 / 什么不写)

## §1.1 一句话定位

- [ ] ≤ 30 字
- [ ] 含 genre (类型)
- [ ] 含 hook (玩家为什么玩)
- [ ] 含 platform (在哪玩)
- [ ] 写不出 → 回 Phase 1 重想, 别硬填

**反例** (写不过):
- "一个超好玩的 Roguelike 游戏" (没 hook 没 platform)
- "Steam 平台上的多人合作的开放世界生存建造" (53 字, 太长)
- "类似《XX》但更好" (空话)

**正例**:
- "Roguelike 卡牌 + 杀戮尖塔式爬塔, Steam 单机, 单局 30 分钟。"
- "塔防 + 自走棋混合 Roguelike, Steam 单机, 单局 30 分钟。"

## §1.2 设计支柱

- [ ] 3-5 条
- [ ] 每条 ≤ 12 字
- [ ] 用作决策过滤器 (后面所有特性"加不加"用它判)
- [ ] 不可互相冲突 (例: "易学" vs "高门槛")

**反例**:
- "可玩性高" (空话)
- "好玩就行" (空话)
- "既有深度又易上手" (互相冲突)

**正例** (修仙自走棋):
1. "每局都不一样" — Roguelike 随机性 + 羁绊构筑
2. "构筑即乐趣" — 决策点前置, 战斗无需操作
3. "修仙沉浸感" — 所有机制用修仙语言包装
4. "深度但不繁琐" — 养成在局内, 单局 45 分钟

## §1.4 核心循环

- [ ] ASCII 流程图 (不可省)
- [ ] 主循环 ≤ 5 步
- [ ] 副循环可选 (有的话也图示)

**反例** (只有文字没图):
> "玩家选路线, 然后战斗或事件, 然后获取东西, 然后升级..."

**正例**:
```
选路线 → 战斗/事件/坊市/炼制
       ↓
   获取棋子与法宝
       ↓
   养成棋子 & 升级建筑
       ↓
   挑战精英与 Boss
       ↓
   推进章节 → 通关或身死道消
```

## §2.1 主要操作

- [ ] 每个操作 4 列填满 (输入/响应/失败/UI)
- [ ] 程序员读了能 prototype (不可有"具体效果待定")

**反例**:
| 操作 | 输入 | 响应 |
|---|---|---|
| 攻击 | 鼠标 | 打一下 |

**正例** (jaconir.online 风格):
| 操作 | 输入 | 系统响应 | 失败态 | UI 反馈 |
|---|---|---|---|---|
| 冲刺 | Shift + 方向 | 8 帧无敌冲刺 | 耐力空进入冷却 | 角色闪白 + 音效 |

## §3.4 美术方向 (3 选 1 必填一项)

- [ ] 参考图链接 / 色板 / 情绪词 至少 1 项
- [ ] 不写 "丰富细腻" / "高端大气" / "水墨风" 等空话

**反例**:
- "美术风格为东方玄幻, 丰富细腻, 大气磅礴" (全是空话)

**正例** (情绪词 + 参考图):
- **情绪词**: 冷峻 / 神秘 / 极简
- **参考图**: <链接 1: 某手游主界面> <链接 2: 某独立游戏场景图>
- **色板**: 主色 #2C3E50 / 辅色 #ECF0F1 / 强调色 #E74C3C

## §4.1 Scope IN

- [ ] 列表, 每条 1 行
- [ ] ≤ 10 条 (多了说明 scope 没收敛)

## §4.2 Scope OUT (硬性闸门)

- [ ] 列表, 每条 1 行
- [ ] **≥ 3 条** (空则拒绝完成)
- [ ] 每条都是"主动放弃的", 不是"还没想到的"

**反例** (错的):
- "TBD" / "等设计完再写" ← 闸门红
- "剧情很丰富" ← 不是 OUT, 是 IN

**正例**:
- 无多人模式
- 无存档 (一次性体验)
- 无内购
- 无剧情分支
- 关卡数 ≤ 5
- 不上 Steam Workshop

## §4.3 里程碑

- [ ] 至少 3 个: Prototype / Alpha / Beta / Ship
- [ ] 每个标日期或周数, 不写"未来"
- [ ] 每个标可验收标准 (例: "核心循环可玩, 5 个关卡")

## §4.4 风险与缓解

- [ ] ≥ 3 条风险
- [ ] 每条: 风险 + 概率 (高/中/低) + 缓解
- [ ] 不写"技术很难"等空话, 写"敌人 AI 平衡调不好, 缓解: 先上 3 个固定阵容, 玩家反馈后再调"

## §4.5 竞品与定位 (team 档)

- [ ] 2-3 个竞品
- [ ] 每竞品: 核心玩法 / 商业化 / 用户评价 (3-5 句) / 我们的差异化
- [ ] 差异化要具体到机制 / 数值 / 体验, 不空话

**反例**:
- "我们的游戏和《XX》类似, 但更好" ← 空话

**正例**:
- "我们的战斗是 Roguelike + 卡牌 (《XX》是回合制卡牌), 单局时间压缩到 30 分钟 (《XX》是 90 分钟)"

## §4.7 商业化 (team 档)

- [ ] 选 1 个主模型
- [ ] 单位经济 (1 玩家 1 周期付多少)
- [ ] 不写 "靠玩家氪金" 等空话

## §5/§6 UI / 技术 (team 档)

- [ ] 控件方案按平台分 (PC / 手柄 / 触屏)
- [ ] 性能预算给数字, 不给形容词 (60 FPS / 4GB 内存)
- [ ] **不**写架构 (那是 TDD)
