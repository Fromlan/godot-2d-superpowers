## 2. 填写要点

### 2.1 Vision (1.1-1.5)

- **1.1 一句话 ≤ 30 字** — 多了就回 Phase 1 重新想。
- **1.2 设计支柱 3-5 条** — 每条 ≤ 12 字, 用作决策过滤器, 后面所有特性 "这个加不加" 都用它判。
- **1.4 核心循环必须图示** — 文字描述循环, 玩家读不进去。

### 2.2 Mechanics (2.1-2.3)

- **2.1 表格 4 列** (输入/响应/失败/UI) — 程序员读了要能 prototype。
- **2.2 输赢条件** — 别用 "通关" / "死亡" 等抽象词, 写 "Boss 3 血量归零"。

### 2.3 Content (3.1-3.5)

- **3.4 美术方向 3 选 1** — 参考图 / 色板 / 情绪词, 必须有一项。**不**写 "丰富细腻" / "水墨风" 等空话。
- **3.5 音频方向** — 3 个参考曲, 不要写 "BGM 要有氛围"。

### 2.4 Production (4.1-4.4)

- **4.2 Scope OUT ≥ 3 条** — 写不出 3 条, 说明还没想清楚边界, 回去补 1.1。

## 3. 子模块拆分判定

**满足以下任一条件, 拆子目录**:
- 内容子主题 ≥ 3 个 (例: 棋子 / 羁绊 / 法宝 → 3 个子目录)
- 任何子主题自身内容 > 200 行 (写到主文档会爆)
- 用户后续经常单独编辑某个子主题

**否则单文件** — Lean GDD 应该能一个人维护, 拆了反而难找。
